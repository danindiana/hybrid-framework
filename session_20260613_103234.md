## ⚙️ How `./hermes` Functions

Hermes is an agentic AI assistant designed to run directly on local host machines. It interfaces with the operator through multiple modes:

### 1. Interactive CLI & REPL
The classic interactive command line interface is driven by `cli.py`. It establishes a loop:
* **Input Capture:** Uses `prompt_toolkit` to display a rich prompt with command history, auto-completion, and status markers.
* **Context Assembly:** Aggregates instructions from system guidelines (`AGENTS.md`, `SOUL.md`), local project configurations (`config.yaml`), memory stores, and preloaded skills.
* **Turn loop:** Submits the compiled prompt to the LLM (natively supporting OpenAI, Anthropic, or local Ollama instances) and streams the response back.
* **Tool Execution:** Executes shell, file, browser, or custom skill tools on behalf of the user, requiring manual or automated approvals depending on the security configuration.

### 2. Modern TUI
Invoked via `hermes --tui`, it launches a modern Terminal User Interface powered by a compilation of TypeScript/Node dependencies, managing multi-pane dashboards, live log output, config editors, and native chat sessions.

### 3. Background Services
* **Gateway Daemon:** An MCP (Model Context Protocol) and Agent Client Protocol (ACP) gateway that listens on local ports to exchange messages with other agent clients (e.g. OpenClaw) or messaging platforms (Discord, Slack, Telegram).
* **Scheduled Cron Jobs:** Periodically runs registered background tasks or checks.
* **Dashboard:** A local Web UI hosted on port `9119` (when active) for graphical status monitoring.

## 📦 Python Dependencies

The core architecture of `hermes-agent` relies on standard and optional dependency groups, as defined in its `pyproject.toml` configuration:

### Core Dependencies
These packages are pinned to known-good ranges to provide API communication and TUI formatting:
* **`openai` / `anthropic` / `mistralai`:** Base HTTP clients for querying remote or local LLMs.
* **`prompt_toolkit`:** The foundation of the terminal input interface, providing keystroke handling, syntax highlighting, and buffer management.
* **`rich`:** Formats tables, markdown, banners, and spinners in the terminal output.
* **`httpx[socks]` / `requests`:** Underlying HTTP stack for network connections, including support for SOCKS proxies.
* **`pydantic`:** Validates runtime configurations and JSON schemas.
* **`pyyaml` / `jinja2`:** Loads and parses the `config.yaml` and prompt templates.

### Optional Extra Bundles
Hermes modularizes its capabilities into the following extras:
* **`voice`:** Includes `faster-whisper`, `sounddevice`, and `numpy` to support local Speech-to-Text and voice recording directly from the terminal.
* **`messaging`:** Integrates `python-telegram-bot` and `discord.py` to route conversations to external chat apps.
* **`dev`:** Equips testing tools (`pytest`, `pytest-asyncio`) and the Model Context Protocol (`mcp`) SDK.
* **`web`:** Enables `fastapi` and `uvicorn` to run local REST APIs and serve the dashboard.

## 🖥️ Terminal Window Mechanics & TUI Control

When running inside a terminal window, Hermes controls terminal behavior dynamically:

1. **Terminal Raw Mode:** During the prompt loop, Hermes switches the terminal to raw mode to capture individual keystrokes (for features like completions, cursor movement, and key bindings).
2. **Control Handover:** When launching sub-actions (such as selecting Option 2 to edit configuration in `nano` or Option 3 to follow logs in `tail -f`), the main program temporarily disables raw mode, relinquishes control of the screen, executes the editor or viewer as a subprocess, and restores the raw terminal state upon completion.
3. **Security Integration (Tirith):** Hermes interacts with the `tirith` security tool to run supply-chain audits or check sandboxing parameters, blocking unauthorized filesystem access or dangerous command lines unless manually overridden.
